## 목표
C# 소스 코드를 문자열 이어 붙이기 대신 fluent 빌더로 조립해서, 들여쓰기·중괄호·키워드 이스케이프가 맞는 소스 문자열을 얻는다.

## 사용자
- **Source Generator 작성자**(주 사용자): netstandard2.0 Incremental Generator 안에서 `ITypeSymbol` 정보로 코드를 만든다. 타입 이름은 `ToDisplayString()` 결과 같은 문자열로 넘긴다. Visual Studio에서는 generator가 .NET Framework 위에서 실행된다.
- **코드 생성 도구 작성자**: 스캐폴딩 CLI나 빌드 도구에서 런타임에 C# 파일을 만든다.
- NuGet으로 받아 쓰는 불특정 다수. 공개 API의 안정성과 문서를 기대한다.

## 핵심 기능
공통 완료 기준: 기능마다 출력이 기대 문자열과 정확히 일치하는 테스트가 있고, 완결된 파일 단위 출력은 Roslyn으로 컴파일했을 때 오류 진단이 0개다. 컴파일 검증용 입력은 참조하는 타입이 모두 해석되게 구성한다. 모든 테스트가 net10.0과 net48에서 통과한다.

1. **진입점과 File 빌더**: `CSharp` 정적 클래스가 모든 빌더의 진입점이다. `CSharp.File(...)`은 `AutoGeneratedHeader()`(`// <auto-generated/>`), `NullableEnable()`(`#nullable enable`), `Using(...)`, 블록 `Namespace(...)`, `FileScopedNamespace(...)`, 네임스페이스 없는 최상위 타입, `Raw()`를 담는다. 헤더 두 줄은 호출했을 때만 출력한다.
2. **타입 빌더**: class, struct, interface, record(class·struct), enum을 종류별 전용 빌더로 만든다.
   - 공통: 접근 제한자, 수식어(static, abstract, sealed, partial, readonly 등), 기반 타입·인터페이스 목록, attribute, XML 문서, 제네릭 매개변수와 제약(`TypeParameter("T", t => t.Constraint("class"))`), 중첩 타입, `Raw()`.
   - record·class·struct는 `PrimaryParameter()`로 주 생성자를 지원한다. 본문 멤버가 없는 record는 `;`로 끝난다.
   - enum은 멤버와 값을 지원한다. 값은 문자열이다(`.Member("Green", "2")`).
   - 타입 종류가 허용하지 않는 멤버는 해당 빌더에 메서드가 없어서 컴파일 단계에서 막힌다(예: `EnumBuilder.Method` 없음).
3. **멤버 빌더**: field, property, method, constructor, operator, indexer, event, delegate.
   - 속성: 람다를 생략하면 `{ get; set; }` 자동 속성. 람다에서 `Get()`/`Set()`/`Init()`, 접근자 본문, `Arrow(expr)`, `Initializer(expr)`를 지정한다.
   - 메서드: `Returns(type)`(생략 시 `void`), `Parameter(type, name, p => ...)`(ref/out/in/params/this 수식어, `Default(expr)`), `Body(...)` 또는 `Arrow(expr)`. 본문이 없으면 `;`로 끝난다.
   - attribute: 인자는 원시 문자열이다(`.Attribute("Obsolete", "\"msg\"")`). `Type`·제네릭 오버로드는 5번 규칙을 따른다.
   - XML 문서: `Doc(d => d.Summary(...).Param(...).Returns(...))`. 텍스트는 XML 이스케이프한다. 태그가 필요하면 `d.Xml(raw)`로 원시 XML을 넣는다. 여러 줄이면 줄마다 `///`를 붙인다.
4. **본문**: `Body(b => b.Line(...).Block("if (x > 0)", ib => ...))`. 식과 문은 문자열로 받는다. `Line()`에 여러 줄 문자열이 오면 줄마다 현재 들여쓰기를 붙이고 `\r\n`은 `\n`으로 정규화한다.
5. **타입 참조와 식별자**:
   - 문자열로 받은 타입은 그대로 출력한다.
   - `Type`·제네릭 오버로드는 `global::` 완전 한정 이름으로 바꾸고, 키워드 별칭이 있는 타입(`int`, `string` 등)은 키워드로 쓴다. 제네릭·중첩·배열 타입도 C# 표기로 바꾼다.
   - 식별자(타입, 멤버, 매개변수, 타입 매개변수, enum 멤버 이름)가 C# 예약 키워드면 `@`를 붙인다. 식별자로 쓸 수 없는 이름은 빌더 메서드를 호출하는 시점에 `ArgumentException`을 던진다.
6. **렌더링과 포맷**: 모든 빌더의 `ToString()`이 그 조각을 렌더링한다.
   - 포맷은 고정이다: 4칸 스페이스, `\n`, 멤버 사이 빈 줄 1개, 중괄호는 새 줄(Allman).
   - 멤버는 추가한 순서대로 출력한다.
   - 접근 제한자를 호출하지 않으면 생략한다. 여러 번 호출하면 마지막 호출이 이긴다. 수식어 조합의 유효성은 검사하지 않는다.
7. **조합**: 람다로 중첩하거나, 따로 만든 빌더를 `Add()`로 끼워 넣는다. 빌더는 가변이다.

## 범위 밖
- 기존 C# 코드 파싱·분석·변환 — 생성 전용 라이브러리다.
- 식 수준 타입화, If·For 같은 문 전용 메서드 — C# 문법 전체를 모델링하게 된다. 본문은 문자열과 블록 헬퍼로 충분하다.
- 주석·전처리기 전용 API — `Raw()`로 대신한다.
- 문자열 리터럴 이스케이프 헬퍼 — 식은 문자열로 받는다는 원칙을 따른다.
- using 자동 수집 — 문자열 타입에서는 네임스페이스를 알 수 없다. `Type` 오버로드는 `global::`로 해결한다.
- LangVersion별 출력 조정과 검증 — 버전 호환은 사용자 책임이다. 문법 선택(namespace 형식)은 명시적 메서드로 한다.
- 포맷 옵션 — 규칙은 고정이다.
- 수식어 조합 검증 — 컴파일러가 잡는다.
- Roslyn 타입(`SyntaxNode`, `SourceText`) 반환 — 의존성 0을 유지한다.
- NuGet 자동 배포 — 준비되면 수동으로 배포한다.
- 스레드 안전성 — 빌더는 가변이며 스레드 안전하지 않다. XML 문서에 명시한다.

## 제약
- `netstandard2.0` 단일 타깃, 런타임 패키지 의존성 0 (ADR-001).
- 라이브러리 소스는 최신 C#으로 작성한다. netstandard2.0에 없는 컴파일러 지원 타입(`IsExternalInit` 등)은 internal polyfill로 채운다.
- 공개 API: XML 문서 필수(CS1591을 오류로), PublicApiAnalyzers로 추적, Nullable 활성화, 경고를 오류로 처리. SemVer, 0.1.0에서 시작한다.
- 패키지: ID와 루트 네임스페이스는 `Codrio`, 라이선스 MIT, SourceLink·결정적 빌드·snupkg.
- 테스트: xUnit v3, net10.0과 net48. net48은 Windows에서만 실행된다.
- CI: GitHub Actions의 Windows 러너에서 빌드·테스트만 한다.
