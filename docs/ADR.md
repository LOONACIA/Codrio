# Architecture Decision Records

> 선택 사항. 되돌리기 어려운 기술 결정만 기록합니다. 스텝 description에서 "이 결정을 벗어나지 마라"의 근거로 쓰입니다.

## 원칙
작동하는 최소 구현을 우선한다. 라이브러리 본체에는 런타임 의존성을 추가하지 않는다. 판단하기 애매한 검증은 컴파일러에게 맡긴다.

---

### ADR-001: netstandard2.0 단일 타깃, 런타임 의존성 없음
- **상태**: 채택
- **결정**: `src/Codrio`는 `netstandard2.0`만 타깃하고 런타임 패키지 의존성을 두지 않는다. 빌드 전용 패키지(PublicApiAnalyzers, SourceLink)는 `PrivateAssets="all"`로만 허용한다.
- **이유**: Source Generator는 netstandard2.0이어야 한다. generator가 참조하는 라이브러리가 `Microsoft.CodeAnalysis` 등에 의존하면 호스트 컴파일러 버전과 충돌할 수 있다.
- **트레이드오프**: 최신 BCL API를 쓸 수 없고, 컴파일러 지원 타입은 polyfill로 채워야 한다.
- **하네스에 미치는 영향**: `src/Codrio`의 TargetFramework 변경 금지. `PrivateAssets="all"`이 아닌 PackageReference 추가 금지.

### ADR-002: 빌더가 곧 모델, 문자열로 직접 렌더링
- **상태**: 채택
- **결정**: Roslyn SyntaxFactory 대신, 가변 빌더가 상태를 직접 들고 `internal Write(CodeWriter)`로 문자열을 렌더링한다. 별도 모델 노드 계층은 두지 않는다.
- **이유**: 의존성이 없고 빠르며 포맷을 완전히 제어할 수 있다. 모델 계층을 따로 두면 같은 구조를 두 번 정의하게 된다.
- **트레이드오프**: 출력 문법이 맞는지 직접 보장해야 한다. 테스트에서 Roslyn 컴파일 검증으로 보완한다.
- **하네스에 미치는 영향**: 빌더와 1:1 대응하는 Node/Model 클래스를 만들지 말 것. 출력 형태를 바꾸는 스텝은 Roslyn 컴파일 검증 테스트를 포함할 것.

### ADR-003: 타입 종류별 전용 빌더와 제네릭 기반 클래스
- **상태**: 채택
- **결정**: `ClassBuilder`, `StructBuilder`, `InterfaceBuilder`, `RecordBuilder`, `EnumBuilder`를 따로 두고, 공통 기능은 `TSelf`를 반환하는 제네릭 기반 클래스에 둔다.
- **이유**: enum에 메서드를 넣는 것처럼 잘못된 조합을 컴파일 단계에서 막는다.
- **트레이드오프**: 타입 수가 늘고 자기 참조 제네릭(`TypeBuilder<TSelf>`) 때문에 구현이 복잡해진다.
- **하네스에 미치는 영향**: `Kind` 값으로 분기하는 단일 TypeBuilder 금지. 여러 타입에 공통인 기능은 기반 클래스에 추가할 것.

### ADR-004: 타입·식·본문은 문자열로 받는다
- **상태**: 채택
- **결정**: 타입 참조, 식, 문, attribute 인자, 기본값은 문자열로 받아 그대로 출력한다. `Type`·제네릭 오버로드는 `global::` 완전 한정 이름과 키워드 별칭으로 바꾼다. 메서드 본문은 `Line`/`Block` 헬퍼로 조립한다.
- **이유**: Source Generator에서는 사용자 타입을 컴파일 타임에 알 수 없고 `ToDisplayString()` 문자열을 다룬다. 식까지 타입화하면 C# 문법 전체를 모델링하게 된다.
- **트레이드오프**: 식의 오타는 생성 코드를 컴파일해야 드러난다. using 자동 수집을 할 수 없다.
- **하네스에 미치는 영향**: Expr·Statement 모델, If·For 같은 문 전용 메서드, using 자동 수집 추가 금지.

### ADR-005: 고정 포맷, C# 언어 버전 미검증
- **상태**: 채택
- **결정**: 4칸 스페이스, `\n`, 멤버 사이 빈 줄 1개, Allman 중괄호로 고정한다. LangVersion을 검증하거나 버전별로 출력을 조정하지 않는다. 기본 출력은 하위 호환 문법(블록 namespace)이고, 최신 문법은 명시적 메서드(`FileScopedNamespace`)로 고른다.
- **이유**: 포맷 옵션은 테스트할 조합을 크게 늘린다. 버전별 규칙표는 유지 비용이 크다.
- **트레이드오프**: 사용자가 포맷을 바꿀 수 없다. 버전 불일치는 사용자가 컴파일할 때 드러난다.
- **하네스에 미치는 영향**: 포맷 옵션과 LanguageVersion 옵션 추가 금지. 기대 문자열 테스트는 이 규칙대로 작성할 것.

### ADR-006: 가변 빌더와 람다 중첩 + Add 조합
- **상태**: 채택
- **결정**: 빌더 메서드는 상태를 바꾸고 자기 자신을 반환한다. 하위 구조는 람다(`c => c.Method(...)`)로 만들거나, 따로 만든 빌더를 `Add()`로 끼워 넣는다.
- **이유**: 구현이 단순하고 할당이 적다. Source Generator에서 심볼을 돌며 멤버를 따로 만든 뒤 붙이는 패턴을 지원한다.
- **트레이드오프**: 같은 빌더 인스턴스를 여러 곳에서 공유하면 변경이 섞인다. 스레드 안전하지 않다.
- **하네스에 미치는 영향**: 불변 빌더(`with` 복사)나 `End()`로 빠져나오는 평탄 체이닝 API 추가 금지.
